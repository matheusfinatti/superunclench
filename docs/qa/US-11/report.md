# QA report — US-11 Alert style: Nudge vs Ring

- **Build:** latest debug build via the adb bridge, `Pixel_9(AVD)`, API 37 (Android 16 "Baklava"). The app was reinstalled by the instrumented tests, so I re-granted `POST_NOTIFICATIONS` (`pm grant`) and exact alarms (`appops`).
- **Setup:** QA → Reset all data, Short intervals ON (L1 = 5 s, except where noted), Auto-pause ON. Driven entirely through adb: `input`, `uiautomator`, `dumpsys notification|audio|power|activity|vibrator_manager`, `cmd audio|notification|uimode`, `appops`, `adb reboot`.
- **Emulator caveat:** there is no secure lock screen (swipe keyguard), so "over the lock screen" was tested with the screen off (`KEYCODE_POWER`) and the keyguard showing. A PIN lock was not tested.
- **Date:** 2026-10-01 · **Tester:** QA agent
- **Result:** 12 PASS · 1 PASS with a bug (AC3, latency) · 0 FAIL. Bugs: **B1 (Major):** the first locked Ring can be silenced by Android 16 audio hardening and appears about 10 s late. **B2 (Minor):** a stale AlarmActivity record lingers.

## Bugs

| # | Severity | Title | Steps | Expected | Actual |
|---|----------|-------|-------|----------|--------|
| B1 | **Major** | First Ring from the background: audio muted by Android 16 AudioHardening (≈30 s, seen once) and alarm screen ≈10 s late (seen every cold run) | Ring + Short intervals. Start (or set a level with ≥ 60 s interval), press Home, `KEYCODE_POWER`, wait for the check-in. | Within about 1 s of firing: screen on, AlarmActivity on top, alarm audible. | **Run 1 (20:05):** the alarm fired at 20:05:29, `AudioHardening background playback muted … USAGE_ALARM` at 20:05:30, player `mutedState:opControlAudio` until **20:06:00** (≈30 s silent; vibration only), and the screen woke at 20:05:39 ([05b](05b-first-ring-audio-hardening-mute.txt)). **Run 3 (cold, 60 s backgrounded):** playback started at 20:15:04 and was *not* muted ("would be muted … exemption"), but the screen stayed **Asleep until 20:15:15** (≈11 s) ([14](14-locked-cold-ring-timeline.txt)). **Warm run:** < 1 s ([13](13-locked-ring-timeline.txt)). Hypotheses for Eng: (a) playback starts before the foreground service or activity is promoted, so AudioHardening mutes it (start the FGS with type `mediaPlayback`/`systemExempted` first, or start audio from the activity); (b) the full-screen intent is delayed by the system for a backgrounded or cached process (consider `setShowWhenLocked` + an activity launch from the FGS, or check the FSI launch path). An alarm app that is silent or late for the first 10–30 s fails the purpose of Ring. |
| B2 | Minor | Stale `AlarmActivity` record remains after the ring is resolved | After several rings answered/timed out, `dumpsys activity activities` | Alarm task finished | A separate task `…ring.AlarmActivity t323` remains `state=STOPPED finishing=false` while MainActivity is resumed. It is not obviously visible in Recents ([21](21-recents-stale-alarm-task.png)), but it may resurface; it should `finishAndRemoveTask()` on resolve/timeout. |

## Notes
- Sound is the device's default alarm tone on the alarm stream, and vibration is the repeating `[0, 600, 800]` pattern (`vibrator_manager`: "Step=600ms(amplitude=1.00) Step=800ms(amplitude=0.00), repeat=0"), matching design §6. Every answer, Silence or Stop cancels the vibration (`cancelled_by_user`).
- While a Ring heads-up is showing it covers the top ~470 px, including the QA panel back arrow and jump chips, so taps there hit the heads-up ([27a](27a-heads-up-covers-qa-back-tooling.png)). This is a tooling note, the same as in US-06.
- The level-6 alarm screen in light mode is in [06b](06b-alarm-screen-light-level6.png).

Ringer **NORMAL**, DND **off**, system dark **off**, `USE_FULL_SCREEN_INTENT` and `SCHEDULE_EXACT_ALARM` **allowed**, Alert style **Nudge**, Short ring cap OFF, Short intervals ON, Auto-pause ON, quiet hours 22:00–07:00 (simulation OFF), session **Stopped**, app on **Home**, theme **System** ([32](32-final-home-stopped-nudge.png)).
